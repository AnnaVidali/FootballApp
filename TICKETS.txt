TICKET 1: Test the Auth Flow
================================================================
Status: TODO
Priority: HIGH
Goal: Make sure register and login actually work end-to-end.

What to do:
1. Run the app: npm run dev
2. Open http://localhost:3000
3. Click "Register"
4. Fill in: name, email, password -> submit
5. Check Supabase dashboard -> Authentication -> Users
   (you should see your new user)
6. You should be redirected to /login
7. Log in with the same email/password
8. You should be redirected to the homepage, now showing your email

What to learn:
- "use client" directive: The login/register pages use this because
  they need useState and event handlers. Server Components can't
  handle user interactions directly.
- Supabase Auth: When you call signUp(), Supabase creates a user
  in their auth system (auth.users table). We then create a
  matching profile in OUR profiles table with their name/role.
- Middleware: middleware.ts runs on EVERY request. It checks if the
  user has a valid session cookie. If not, it redirects to /login.
- RLS (Row Level Security): The SQL policies we wrote mean that
  each user can ONLY see their own data. Try querying the DB
  without auth - you'd get nothing back.

TICKET 2: Create the Dashboard Page
================================================================
Status: TODO
Priority: HIGH
Goal: A page that shows after login with user info and team status.

What to build:
- app/dashboard/page.tsx (Server Component)

What it should show:
1. Welcome message with user's name
2. If user has NO team: show "Create a Team" and "Join a Team" buttons
3. If user HAS a team: show team name, upcoming events, quick actions

Steps:
1. Create app/dashboard/page.tsx
2. Use createClient from @/lib/supabase/server to get the user
3. Query the profiles table to get the user's name and team_id
4. If team_id is null, show team setup options
5. If team_id exists, query teams table to get team name

What to learn:
- Server Components: This page runs on the SERVER, not the browser.
  No "use client" needed. We can directly query Supabase without
  exposing keys to the browser.
- async/await in Server Components: You can use async functions
  directly in Server Components (Next.js 14+ supports this).
- Data fetching pattern: Server Components fetch data directly.
  No useEffect, no loading states, no client-side waterfalls.

TICKET 3: Create Team (for coaches)
================================================================
Status: TODO
Priority: HIGH
Goal: Coach creates a team, gets an invite code, becomes team owner.

What to build:
- app/dashboard/create-team/page.tsx
- A form with team name input

What it should do:
1. Coach enters team name
2. INSERT into teams table with coach_id = current user
3. UPDATE profiles table: set team_id = new team, role = 'coach'
4. Show the generated invite code

Steps:
1. Create the page as a Client Component (needs form handling)
2. Insert team: supabase.from("teams").insert({ name, coach_id: user.id })
3. Update profile: supabase.from("profiles").update({ team_id, role: 'coach' }).eq('user_id', user.id)
4. Display the invite_code from the inserted team

What to learn:
- Foreign keys: teams.coach_id references auth.users(id). When you
  insert a team, you MUST provide a valid user ID.
- Auto-generated values: The invite_code is auto-generated by our
  PostgreSQL trigger (set_invite_code). We don't need to send it.
- Profile updates: After creating a team, you need to link the
  profile to the team. This is a two-step transaction.

TICKET 4: Join Team (for players)
================================================================
Status: TODO
Priority: HIGH
Goal: Player enters an invite code to join an existing team.

What to build:
- app/dashboard/join-team/page.tsx
- A form with invite code input

What it should do:
1. Player enters invite code
2. Find the team with that code: supabase.from("teams").select().eq("invite_code", code.toUpperCase()).single()
3. Update profile: set team_id = found team's id
4. Redirect to dashboard

Steps:
1. Create the page as a Client Component
2. Look up team by invite code
3. Update the user's profile to link to that team
4. Handle errors: "Team not found", "Already on a team"

What to learn:
- .single(): When you expect exactly ONE row, use .single().
  Otherwise Supabase returns an array.
- Case sensitivity: We uppercase the code because our trigger
  generates uppercase codes. Always normalize user input.
- Error handling: Always check if the team exists BEFORE updating.
  Use try/catch or check Supabase error responses.

TICKET 6: Event Management (Schedule Training/Match)
================================================================
Status: TODO
Priority: HIGH
Goal: Coach can create trainings and matches with date/location.

What to build:
- app/dashboard/events/page.tsx (list of events)
- app/dashboard/events/new/page.tsx (create event form)

What the form should have:
1. Event type: dropdown (Training / Match)
2. Title: text input (e.g., "Tuesday Training")
3. Date/time: datetime-local input
4. Location: text input (optional)

Steps:
1. Create the list page: query events WHERE team_id = user's team_id, ordered by date
2. Create the form page: insert into events table
3. Show events in a list, sorted by date (upcoming first)
4. Past events shown differently (greyed out)

What to learn:
- Date handling: JavaScript Date objects vs ISO strings.
  Supabase stores TIMESTAMPTZ, so dates come back as ISO strings.
  Use new Date(isoString) to convert.
- Ordered queries: .order("date", { ascending: true }) sorts results.
- Conditional styling: Past events = grey, upcoming = normal.
  Use new Date(event.date) < new Date() to check.

TICKET 7: Availability System
================================================================
Status: TODO
Priority: HIGH
Goal: Players mark whether they're available for upcoming events.

What to build:
- Update the events page to show availability buttons
- A component: AvailabilityButton.tsx

What it should do:
1. For each upcoming event, show 3 buttons: Available / Maybe / Unavailable
2. Player clicks one -> upsert into availability table
3. Show count of responses (3 available, 1 maybe, 2 unavailable)
4. Coach can see WHO responded what

Steps:
1. Create components/AvailabilityButton.tsx (Client Component)
2. Query availability WHERE event_id = event.id
3. Use upsert: .upsert({ user_id, event_id, status }) to handle
   both new and updated responses
4. Display aggregated counts on the event card

What to learn:
- Upsert: INSERT or UPDATE. If the user already responded, update
  their response. If not, create a new row. Supabase handles this
  with .upsert() which uses the UNIQUE constraint.
- Real-time subscriptions: (Future) We can subscribe to changes
  in the availability table so the coach sees updates instantly.
- Aggregations: Count responses by status. SQL: SELECT status,
  COUNT(*) FROM availability WHERE event_id = X GROUP BY status

TICKET 8: Lineup Management
================================================================
Status: TODO
Priority: HIGH
Goal: Coach creates a 7v7 formation for matches.

What to build:
- app/dashboard/lineup/[eventId]/page.tsx
- components/FieldView.tsx (visual pitch with positions)

What it should show:
1. A visual representation of a 7-a-side pitch
2. Positions: GK, CB, CB, LB, RB, ST, ST (or custom)
3. Each position is a dropzone where coach can assign a player
4. Player pool on the side (unassigned players from roster)

Steps:
1. Create the field view with CSS/Tailwind (a green rectangle with
   positioned position slots)
2. Get event ID from URL params
3. Query roster (profiles WHERE team_id = user's team_id)
4. Query existing lineup (lineups WHERE event_id = event.id)
5. Coach assigns players to positions -> insert into lineups
6. Show shirt number next to each player

What to learn:
- Dynamic routes: [eventId] in the URL makes this a dynamic route.
  Access it via params.eventId in the page component.
- CSS positioning: The field is a fixed-size container with
  absolutely positioned slots for each position.
- Many-to-many: A lineup links a player to a position for a
  specific event. One player can be in many lineups (different events).

TICKET 11: Protected API patterns
================================================================
Status: TODO
Priority: MEDIUM
Goal: Understand how to safely query data.

What to learn:
1. ALWAYS use the Supabase client (never raw SQL from the client)
2. RLS policies are your safety net - even if your code has a bug,
   RLS prevents users from seeing data they shouldn't
3. Server Components = safe (keys never leave the server)
4. Client Components = use the anon key (RLS protects you)

Exercise: Try to access another user's profile in the browser
console. Supabase will return empty results thanks to RLS.
